What Is a Website?

🎯 Key Learning Objectives

  • Discover how web browsers request, receive, and translate code into living interactive graphics.
  • Understand the Client-Server architecture through the fun analogy of a fast-food restaurant.
  • Examine the internal pipeline of modern browser engines (DOM, CSSOM, Render Tree, and Paint).

Imagine stepping into your favourite restaurant. You don't walk into the kitchen and bake your own pizza—you sit down, look at the menu, and order. The web works in the exact same magical way!

The Restaurant Analogy: How the Internet Delivers

When you type https://react.dev into your web browser (like Chrome, Safari, or Firefox), your browser is acting like a hungry customer. We call your computer the Client. Across the globe, sitting in a climate-controlled data centre, is another powerful computer that never sleeps: the Server.

Think of the Client as you holding a walkie-talkie, and the Server as a super-fast librarian who owns millions of books. When you ask for a page, the librarian photocopies the exact page and beams it back to your screen in a split second!
Figure 1.1: The Anatomy of a Web Page as a Living House.

Every website you see is assembled from three core building materials, much like a house:

  • HTML (The Bricks & Foundation): Defines what actually exists on the page—headers, text paragraphs, buttons, and image containers.
  • CSS (The Paint & Interior Decor): Decides how things look—whether a wall is royal blue or sunny yellow, and how furniture arranges on mobile phones vs big monitors.
  • JavaScript (The Electricity & Smart Sensors): Gives the house life! When you click the doorbell, a chime rings. When you flip a switch, lights turn on.
Under the Hood: The Critical Rendering Path
When bytes arrive over TCP/IP (or QUIC in HTTP/3), the browser engine performs four sequential steps:
  1. Parsing: Raw UTF-8 bytes are tokenized into HTML nodes to produce the DOM (Document Object Model).
  2. Style Calculation: CSS rules are parsed into the CSSOM (CSS Object Model).
  3. Render Tree Synthesis: DOM and CSSOM are combined, discarding invisible nodes (like display: none).
  4. Layout & Paint: The browser calculates exact pixel coordinates (Geometry/Reflow) and rasterizes bitmaps to the GPU buffer.

What is a Framework?

🎯 Key Learning Objectives

  • Understand why large applications require structured component architectures.
  • Contrast Declarative UI ("What to show") vs Imperative UI ("How to do it step-by-step").
  • Discover how React and Angular solve the "Spaghetti Code" crisis.

If you have ever built a giant castle out of thousands of wooden matchsticks and glue, you know how fragile it is. One sneeze, and the whole tower collapses! That is what writing massive websites in vanilla JavaScript used to feel like.

The Spaghetti Crisis & The Invention of Components

In the early days of the web, if a user clicked a button to like a photograph, the developer had to manually locate seven different parts of the screen in code, update their numbers, change their colors, and remember what happened if the internet was slow. As apps grew to millions of lines of code, they turned into tangled spaghetti code.

Figure 3.1: Modern UI Components as Precision LEGO Bricks.

A Framework (or component library like React) is like a standardized LEGO factory. Instead of hand-carving every single brick, you get precision-engineered modules that snap together cleanly. If one brick needs fixing, you fix that brick alone without demolishing the whole castle!

Imagine telling your robot friend: "Clean your room!" (Declarative) versus having to command: "Bend left knee 45 degrees, reach arm down, grab sock, raise arm, walk 3 steps to basket, release sock..." (Imperative). Frameworks let us speak the easy Declarative language!
Imperative vs Declarative Mental Models
Traditional DOM manipulation is strictly imperative: 
const el = document.createElement('div'); el.textContent = 'Hello'; parent.appendChild(el);
Both React and Angular embrace declarative reconciliation: you describe state as a mathematical projection: 
UI = f(State)
The runtime framework assumes full responsibility for calculating the minimal graph edits required to sync the real DOM with that state projection.

In React, you don't build entire pages in one giant document. You write bite-sized functions that each build one small piece of the world. Then, you combine them like magical ingredients!

Functions That Paint Pixels

A React component is an ordinary JavaScript function with two special superpowers:

  1. Its name must start with a Capital Letter (like WelcomeBadge, not welcomeBadge).
  2. It returns markup that describes what should appear on the screen!

Figure 4.1: The Component Pipeline: Input Props → Pure Function → Virtual DOM.
WelcomeCard.jsx React 19 Component 
// A modern React 19 functional component
export function WelcomeCard({ name, role = "Explorer" }) {
  return (
    <div className="welcome-card">
      <h2>Welcome aboard, {name}! 🚀</h2>
      <p>Your assigned mission: {role}</p>

Why the capital letter? Imagine telling your computer: "Show me a button". The browser thinks of a plain grey HTML button. But if you say: "Show me a <SuperShinyCoolButton />" with a Capital Letter, React says: "Aha! That's a custom component my human created!"
React 19 Architecture: The React Compiler Revolution
In legacy React 16 through 18, functional components re-executed their entire body whenever parent state updated, forcing developers to litter their codebases with useMemo, useCallback, and React.memo to preserve referential equality.

In React 19, the official React Compiler (formerly Project Forget) analyzes your AST at build-time. It automatically inserts memoization blocks and fine-grained dependency tracking into compiled output. Components are now idempotent and optimal by default!

JSX — Writing HTML in JavaScript

🎯 Key Learning Objectives

  • Demystify JSX as a syntax extension, not browser HTML.
  • Master curly braces { } as windows into JavaScript execution.
  • Learn the 3 Essential Golden Rules of JSX syntax.

At first glance, JSX looks like someone accidentally poured a bowl of HTML right into the middle of a JavaScript file. But it is actually a magic wand that unites structure and logic!

Figure 5.1: The JSX Magic Wand translating templates into AST element trees.

The 3 Golden Rules of JSX

  1. 1. Always Return a Single Root Element: A component cannot return two floating tags side-by-side. Wrap them in a <div> or an invisible React Fragment: <> ... </>.
  2. 2. Close Every Single Tag: Unlike loose HTML where you might leave <img> or <input> unclosed, JSX demands self-closing syntax: <img src="..." />.
  3. 3. camelCase Most Attributes: Because class and for are reserved keywords in JavaScript, JSX uses className and htmlFor.

The Magic Window: Curly Braces { }

Whenever you want to switch from HTML mode back into JavaScript mode inside JSX, open a pair of curly braces { }. It acts like a portal!

      <p>Total Known Spells: {spells.length}</p>
      <p>Lucky Number: {7 * 6}</p>

Props — Passing Notes Between Components

How components talk to each other with data

🎯 Learning Objectives

  • Use default props and prop destructuring

📬 A Real-World Story: The School Note System

Imagine you're at school 🏫 and you want to tell your friend across the classroom something important. You can't just shout — the teacher would get upset! So you fold up a little note, write your friend's name on the front, and pass it along. Your friend opens it, reads it, and now they know exactly what you wanted to tell them.

In React, components are like students sitting in different rows. When a parent component wants to send information to a child component, it writes that information into something called props (short for "properties"). The child opens up those props and uses whatever was sent — a name, a colour, a price, even a whole function!

The best part? Just like a note can say different things to different people, the same component can receive different props and show completely different content. One <ProductCard> component can show a PlayStation; give it different props and it shows a pizza. Same envelope, different letter. 🎮🍕

What Are Props?

Props are the mechanism React uses to pass data from a parent component down to a child component. They are read-only — the child component can read them but must never modify them directly. This is called one-way data flow.

📖
Definition — Props: Short for "properties". An object passed to a React component containing all the data attributes the parent wants to share. Inside a function component, props arrive as the first argument. Inside JSX, they look like HTML attributes.

🎮 For Kids — The LEGO Instructions Analogy

Imagine you have a LEGO set for building a spaceship 🚀. The instructions booklet tells you what colour pieces to use and how big to make each part. Without the instructions, you'd have random bricks!

A React component is like a LEGO builder robot 🤖. On its own it doesn't know what to build. But when you hand it props (the instructions), it knows exactly what to make:

  • 🔵 color="blue" → build it blue!
  • 🔢 pieces={42} → use 42 bricks!
  • 📛 name="Millennium Falcon" → that's the name!

The robot reads the instructions but never writes on them. It just follows what's written. That's exactly how props work — the child reads but doesn't change them.

💻 For Developers — Props in Depth

Destructuring Props (The Professional Way)

Rather than writing props.name everywhere, destructure in the function signature:

React 19 · ProductCard.jsx
import React from 'react';

// Destructure props directly in the parameter list
function ProductCard({ name, price, image, rating = 5, onAddToCart }) {
  return (
    <article className="product-card">
      <img src={image} alt={name} />
      <h3>{name}</h3>
      <p className="price">${price.toFixed(2)}</p>
      <div className="rating">
        {Array.from({ length: rating }, (_, i) => (
          <span key={i}>⭐</span>
        ))}
      </div>
      <button onClick={() => onAddToCart({ name, price })}>
        Add to Cart 🛒
      </button>
    </article>
  );
}

export default ProductCard;

Passing Functions as Props (Callbacks)

React 19 · App.jsx
import { useState } from 'react';
import ProductCard from './ProductCard';

const products = [
  { id: 1, name: "PS5 Controller", price: 69.99, image: "/ps5.jpg", rating: 5 },
  { id: 2, name: "Keyboard",       price: 129.00, image: "/kb.jpg",  rating: 4 },
];

function App() {
  const [cart, setCart] = useState([]);

  const handleAddToCart = (item) => {
    setCart(prev => [...prev, item]);
  };

  return (
    <div>
      <h1>Shop ({cart.length} items in cart)</h1>
      {products.map(p => (
        <ProductCard
          key={p.id}
          name={p.name}
          price={p.price}
          image={p.image}
          rating={p.rating}
          onAddToCart={handleAddToCart}
        />
      ))}
    </div>
  );
}
⚠️ Warning — Never Mutate Props: props.name = "new value" is a React anti-pattern. Props are immutable from the child's perspective. If you need mutable data, use state (covered in Chapter 7).

Advanced Props Patterns

The children Prop

The special children prop lets you nest content inside a component tag:

React 19 · Card.jsx
function Card({ title, children }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <div className="card-body">{children}</div>
    </div>
  );
}

// Usage — anything between <Card> tags becomes children
<Card title="Welcome!">
  <p>This paragraph is a child!</p>
  <button>Click Me</button>
</Card>

Spread Props Pattern

React 19 · spread props
const userProps = { name: "Alice", age: 28, role: "admin" };

// Spread the whole object as individual props
<UserProfile {...userProps} />

// Equivalent to:
<UserProfile name="Alice" age={28} role="admin" />
🤩 Fun Fact: In React, everything you write as an attribute in JSX — className, onClick, style, custom data — is technically a prop! Even key is a special reserved prop React uses for reconciliation (but you can't read it inside the component).

🧠 Chapter 6 Quiz

Q1. Can a child component modify the props it receives?

Show Answer

❌ No. Props are read-only (immutable) from the child's perspective. To have changeable data, use state instead.

Q2. What is the special prop name for content nested between component tags?

Show Answer

✅ children. Any JSX or text placed between opening and closing component tags is accessible as props.children.

Q3. What does <MyComp {...obj} /> do?

Show Answer

✅ Spreads all key-value pairs of obj as individual props on MyComp. It's shorthand for passing each property manually.

Q4. In function Card({ title, rating = 5 }), what happens if rating is not passed by the parent?

Show Answer

✅ The default value 5 is used. Default parameter values in destructuring act as default props.

Q5. Name two benefits of passing a function as a prop.

Show Answer

✅ 1) The child can notify/communicate with the parent (lifting state up). 2) It keeps the parent in control of logic while letting the child trigger actions.

💻 For Developers — State in Depth

Functional Updater Pattern

When new state depends on old state, always use the functional form to avoid stale closures:

React 19 · functional updater
// ❌ WRONG — may read stale value in async contexts
setCount(count + 1);

// ✅ CORRECT — always gets the latest state
setCount(prev => prev + 1);

// Real example: incrementing in a click handler called multiple times
function handleTripleClick() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  // count goes up by 3 (not 1) because each call receives the updated value
}

Updating Objects and Arrays in State

React 19 · immutable state updates
const [user, setUser] = useState({ name: 'Alice', age: 28, city: 'London' });

// ❌ WRONG — mutating state directly (React won't re-render!)
user.age = 29;
setUser(user); // same object reference → no re-render

// ✅ CORRECT — spread to create a NEW object
setUser(prev => ({ ...prev, age: 29 }));

// ========= Arrays =========
const [items, setItems] = useState(['apple', 'banana']);

// Add item
setItems(prev => [...prev, 'cherry']);

// Remove item
setItems(prev => prev.filter(item => item !== 'banana'));

// Update item
setItems(prev => prev.map(item => item === 'apple' ? '🍎 apple' : item));
⚠️ Golden Rule of State: Never mutate state directly. Always return a new object or array. React compares references; if the reference doesn't change, it skips re-rendering.

When two sibling components need the same data, lift state to their closest common parent:

}

function TemperatureConverter() {
  // State lives in the PARENT — shared between both inputs

Real-World State Example — Shopping Cart

React 19 · ShoppingCart.jsx
import { useState } from 'react';

const PRODUCTS = [
  { id: 1, name: 'Pizza Slice', price: 3.99, emoji: '🍕' },
  { id: 2, name: 'Burger',     price: 5.49, emoji: '🍔' },
  { id: 3, name: 'Ice Cream',  price: 2.99, emoji: '🍦' },
];

function ShoppingCart() {
  const [cart, setCart] = useState({});

  const addItem = (id) =>
    setCart(prev => ({ ...prev, [id]: (prev[id] || 0) + 1 }));

  const removeItem = (id) =>
    setCart(prev => {
      const updated = { ...prev };
      if (updated[id] > 1) updated[id]--;
      else delete updated[id];
      return updated;
    });

  const total = PRODUCTS.reduce((sum, p) =>
    sum + (cart[p.id] || 0) * p.price, 0);

  return (
    <div>
      {PRODUCTS.map(p => (
        <div key={p.id}>
          <span>{p.emoji} {p.name} ${p.price}</span>
          <button onClick={() => addItem(p.id)}>+</button>
          <span>{cart[p.id] || 0}</span>
          <button onClick={() => removeItem(p.id)}>-</button>
        </div>
      ))}
      <h3>Total: ${total.toFixed(2)}</h3>
    </div>
  );
}

State Machines & Complex State with useReducer

When a component has multiple state variables that always change together, or when the next state depends on complex conditional transitions, useReducer is often cleaner than multiple useState calls.

React 19 · useReducer pattern
import { useReducer } from 'react';

const initialState = { count: 0, step: 1, status: 'idle' };

function counterReducer(state, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + state.step, status: 'active' };
    case 'DECREMENT':
      return { ...state, count: state.count - state.step, status: 'active' };
    case 'SET_STEP':
      return { ...state, step: action.payload };
    case 'RESET':
      return initialState;
    default:
      return state;
  }
}

export function AdvancedCounter() {
  const [state, dispatch] = useReducer(counterReducer, initialState);

  return (
    <div className="counter-box">
      <h3>Count: {state.count} (Step: {state.step})</h3>
      <p>Status: {state.status}</p>
      <button onClick={() => dispatch({ type: 'INCREMENT' })}>+{state.step}</button>
      <button onClick={() => dispatch({ type: 'DECREMENT' })}>-{state.step}</button>
      <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button>
      <input
        type="number"
        value={state.step}
        onChange={e => dispatch({ type: 'SET_STEP', payload: Number(e.target.value) })}
      />
    </div>
  );
}

The Rules of Hooks

⚠️
Two Unbreakable Rules:
  1. ✅ Only call Hooks at the top level — never inside loops, conditions, or nested functions
  2. ✅ Only call Hooks from React functions — components or custom hooks, never plain JS functions
These rules ensure React can track hook order correctly on every render.

🎣 Hook #2: useEffect — The Lifecycle Hook

useEffect lets you perform side effects: fetching data, subscribing to events, manipulating the DOM, setting timers — anything that reaches "outside" the component.

React 19 · useEffect patterns
import { useState, useEffect } from 'react';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  // Runs AFTER render, re-runs when userId changes
  useEffect(() => {
    let cancelled = false;   // for cleanup
    setLoading(true);

    fetch(`/api/users/${userId}`)
      .then(r => r.json())
      .then(data => {
        if (!cancelled) {   // only update if still mounted
          setUser(data);
          setLoading(false);
        }
      });

    // Cleanup function — runs before next effect or on unmount
    return () => { cancelled = true; };
  }, [userId]);  // dependency array — re-run only when userId changes

  if (loading) return <p>Loading...</p>;
  return <h2>{user?.name}</h2>;
}

// Three dependency array forms:
useEffect(() => { /* runs after EVERY render */ });
useEffect(() => { /* runs only ONCE on mount */ }, []);
useEffect(() => { /* runs when dep1 or dep2 changes */ }, [dep1, dep2]);

export function useLocalStorage(key, initialValue) {
  const [storedValue, setStoredValue] = useState(() => {
    try {

      return item ? JSON.parse(item) : initialValue;

      return initialValue;

    } catch (error) {
      console.error(error);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}

  imports: [CommonModule],              // Directly import dependencies without NgModule!

      </div>

  private userService = inject(UserService);

  // Inputs & Outputs

  @Input() role: string = 'Member';

What is Dependency Injection?

import { HttpClient } from '@angular/common/http';

export interface CartItem {
  id: number;
  name: string;
  price: number;
  quantity: number;
}

/**
 * providedIn: 'root' registers this service with the application-wide root injector.
 * It is tree-shakable: if unused, the bundler excludes it from production bundles!
 */
@Injectable({
  providedIn: 'root'
})
export class CartService {
  private http = inject(HttpClient);

  // Reactive Signal State
  private itemsSignal = signal<CartItem[]>([]);

  // Read-only public signal for components
  items = this.itemsSignal.asReadonly();

  // Computed signals automatically recalculate when itemsSignal changes
  itemCount = computed(() =>
    this.itemsSignal().reduce((sum, item) => sum + item.quantity, 0)
  );

  totalPrice = computed(() =>
    this.itemsSignal().reduce((sum, item) => sum + (item.price * item.quantity), 0)
  );

  addItem(newItem: CartItem) {
    this.itemsSignal.update(items => {
      const existing = items.find(i => i.id === newItem.id);
      if (existing) {
        return items.map(i => i.id === newItem.id
          ? { ...i, quantity: i.quantity + newItem.quantity }
          : i
        );
      }
      return [...items, newItem];
    });
  }

  clearCart() {
    this.itemsSignal.set([]);
  }
}

Pro Deep Dive 🧠

Zone.js Mechanics: Zone.js patches 50+ browser APIs (setTimeout, Promise, XHR, fetch, addEventListener, etc.) at startup. After each async operation completes, it notifies Angular's ApplicationRef.tick(), which triggers dirty checking top-down through the entire component tree. This runs synchronously, blocking the main thread.

React Fiber Architecture: Fiber is a complete rewrite of React's reconciler (React 16+). The work unit is a "fiber" — a plain JS object representing a component instance. Fiber splits rendering into Render Phase (interruptible, pure) and Commit Phase (synchronous, applies DOM changes). The scheduler uses MessageChannel to yield to the browser between fiber units, enabling concurrent features like Suspense, useTransition, and useDeferredValue in React 18+.

Angular Signals vs Zone.js: Angular 17+ Signals bypass Zone.js entirely. A signal tracks its consumers at read-time (like MobX). When signal.set() is called, only components that read that signal are scheduled for re-render — O(1) precision vs Zone's O(n) full-tree walk. Angular 18+ can run zoneless with provideExperimentalZonelessChangeDetection().

Gotcha — React Stale Closures: React re-renders create new function instances. If you forget dependencies in useEffect, you capture stale state. Angular services are class instances — no closure issues. Use eslint-plugin-react-hooks to catch this.

FormArray vs useFieldArray: Both handle dynamic field arrays (add/remove rows). Angular's FormArray maintains an observable array of FormControls. React Hook Form's useFieldArray provides append, remove, move, insert methods and stable id keys for list reconciliation.

Pro Deep Dive 🧠

The Mental Shift: Server State vs Client State: Before adopting NgRx or Redux, ask: "Is this truly client state, or is it merely a cache of backend data?" Over 80% of data traditionally stored in Redux/NgRx stores (user profiles, product catalogs, paginated lists) is Server State. Modern best practice favors using specialized caching engines (Angular's TanStack Query or HTTP interceptor caches; React's TanStack Query) for network resources, reserving NgRx/Zustand purely for true Client UI State (drawer open state, active filter chips, multi-step unsaved wizard data).

Memoized Selectors and Tree-shaking: NgRx's createSelector() calculates derivations only when its specific input selectors emit new object references. However, because RxJS pipelines use closures, improper destruction without the async pipe or takeUntilDestroyed() causes memory leaks. Zustand bypasses RxJS completely: it utilizes useSyncExternalStore under the hood to guarantee tear-free concurrent renders in React 18 & 19 without wrapper Context providers.

NgRx ComponentStore & SignalStore (Angular 16+): For features where global NgRx is overkill, the Angular team released @ngrx/signals. The signalStore allows writing reactive stores with signals, offering a lightweight developer experience remarkably similar to Zustand while retaining Angular's DI capabilities.

Pro Deep Dive 🧠

Declarative vs Imperative Cache Invalidation: Angular's HttpClient is an HTTP transport client, not an application-level cache. To get caching in Angular, developers typically write custom RxJS subjects with shareReplay(1), or pull in @ngneat/cashew or Angular's TanStack Query port. Cancellation Mechanics: Angular Observables are lazy and natively support cancellation: when a component unmounts, the async pipe cancels the subscription, causing HttpClient to abort the browser's underlying XMLHttpRequest or fetch via AbortController. In TanStack Query, pass signal from queryFn({ signal }) into your fetch(url, { signal }) call to achieve identical native browser request cancellation.

import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { BehaviorSubject, switchMap, scan, Observable } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class InfinitePizzaService {
  private http = inject(HttpClient);
  private page$ = new BehaviorSubject<number>(1);

  // Accumulate pages into one continuous array via scan()
  pizzas$: Observable<Pizza[]> = this.page$.pipe(
    switchMap(page =>
      this.http.get<Pizza[]>(`/api/pizzas?page=${page}&limit=10`)
    ),
    scan((acc, newPage) => [...acc, ...newPage], [] as Pizza[])
  );

  loadMore() {
    this.page$.next(this.page$.value + 1);
  }
}

Async Testing Gotchas (fakeAsync vs waitFor): In Angular, timer-based code (like a 500ms debounce) is tested using fakeAsync and tick(500), which allows stepping through virtual time synchronously. In React Testing Library, asynchronous DOM changes (like waiting for an API response to render) are handled via await waitFor(() => expect(...)) or await screen.findByText('Loaded').

Mock Service Worker (MSW): Modern testing best practice for both Angular and React avoids mocking HttpClient or fetch directly with spies. Instead, engineers use MSW to intercept network requests at the browser/Node network level. This ensures your components make real HTTP calls against realistic simulated API contracts without fragile mock objects.

Quiz Time! 🎯

  1. Why must you call fixture.detectChanges() in Angular tests after triggering an action?
    AnswerAngular tests do not run Zone.js change detection continuously. You must manually call fixture.detectChanges() to inform Angular to evaluate template bindings and update the test DOM.
  2. Why is userEvent preferred over fireEvent in React Testing Library?
    AnswerfireEvent only dispatches a raw DOM event. userEvent accurately simulates full browser behavior (e.g. hovering, focusing, key down, key press, text input, key up, and blur events).
  3. What is the advantage of using screen.getByRole() over CSS selectors like fixture.debugElement.query(By.css('.btn-submit'))?
    AnswerQuerying by ARIA role tests your application the way assistive technologies (and users) experience it, making your test resilient against CSS class refactors while encouraging accessible HTML.
  4. Why is Vitest faster than traditional Karma or Jest runners?
    AnswerVitest reuses Vite's pipeline with esbuild and worker threads. It doesn't transform unchanged files and executes in-memory without starting a heavy headless browser.
