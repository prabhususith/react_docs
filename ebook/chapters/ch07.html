State — Your App's Memory

How components remember things and react to change

🎯 Learning Objectives

  • Understand why state exists and how it differs from props
  • Use useState to add memory to components
  • Understand React's re-render cycle
  • Update objects and arrays in state correctly (immutability)
  • Lift state up to share between sibling components
  • Use the functional updater pattern for safe state transitions

🧠 A Real-World Story: The Scoreboard at a Football Match

Picture yourself at a football stadium ⚽. Up on the giant scoreboard it shows: Home 0 — 0 Away. Every time a team scores, someone presses a button and the number goes up. The scoreboard remembers the current score and updates itself for everyone to see.

Now imagine if the scoreboard had no memory — it would go back to 0 every time someone looked at it! That would be useless. In the same way, a React component without state forgets everything between renders. Add state, and it suddenly remembers — the score, whether a menu is open, what a user typed into a form.

Every time the score changes ⚽, the scoreboard re-renders (updates on screen) automatically. React does the same thing: change a piece of state and React automatically updates the UI to match — no manual DOM manipulation needed. That's the magic! ✨

What Is State?

State is data that a component owns, manages, and can change over time. When state changes, React automatically re-renders the component (and its children) to reflect the new data.

📖
Definition — useState: A React Hook that returns a tuple: [currentValue, setterFunction]. Calling the setter schedules a re-render with the new value. It is the foundational building block of all interactive React UIs.

🎮 For Kids — The Video Game Save File

Think of state like your video game save file 💾. When you're playing Mario, the game remembers:

  • 🍄 How many mushrooms you collected
  • ⭐ How many stars you have
  • ❤️ How many lives are left
  • 🏆 Which levels you completed

Every time something changes (you grab a coin! 🪙), the game updates your save file AND refreshes the screen to show your new score. That's exactly what React's useState does!

In React-land: useState(0) creates a save slot starting at 0. When you call setScore(score + 1), React saves the new value AND redraws the screen. 🎮✨

Your First useState — Counter

React 19 · Counter.jsx (Kid-friendly)
import { useState } from 'react';

function Counter() {
  // score is the current value (starts at 0)
  // setScore is the function to change it
  const [score, setScore] = useState(0);

  return (
    <div>
      <h2>🏆 Score: {score}</h2>
      <button onClick={() => setScore(score + 1)}>+1 Point</button>
      <button onClick={() => setScore(score - 1)}>-1 Point</button>
      <button onClick={() => setScore(0)}>🔄 Reset</button>
    </div>
  );
}
💡 Remember: const [score, setScore] = useState(0) is called array destructuring. React gives back an array with 2 items — the current value and the setter function.

💻 For Developers — State in Depth

Functional Updater Pattern

When new state depends on old state, always use the functional form to avoid stale closures:

React 19 · functional updater
// ❌ WRONG — may read stale value in async contexts
setCount(count + 1);

// ✅ CORRECT — always gets the latest state
setCount(prev => prev + 1);

// Real example: incrementing in a click handler called multiple times
function handleTripleClick() {
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  setCount(prev => prev + 1);
  // count goes up by 3 (not 1) because each call receives the updated value
}

Updating Objects and Arrays in State

React 19 · immutable state updates
const [user, setUser] = useState({ name: 'Alice', age: 28, city: 'London' });

// ❌ WRONG — mutating state directly (React won't re-render!)
user.age = 29;
setUser(user); // same object reference → no re-render

// ✅ CORRECT — spread to create a NEW object
setUser(prev => ({ ...prev, age: 29 }));

// ========= Arrays =========
const [items, setItems] = useState(['apple', 'banana']);

// Add item
setItems(prev => [...prev, 'cherry']);

// Remove item
setItems(prev => prev.filter(item => item !== 'banana'));

// Update item
setItems(prev => prev.map(item => item === 'apple' ? '🍎 apple' : item));
⚠️ Golden Rule of State: Never mutate state directly. Always return a new object or array. React compares references; if the reference doesn't change, it skips re-rendering.

Lifting State Up

When two sibling components need the same data, lift state to their closest common parent:

React 19 · lifting state up
function TemperatureInput({ value, onChange, unit }) {
  return (
    <div>
      <label>{unit}</label>
      <input value={value} onChange={e => onChange(e.target.value)} />
    </div>
  );
}

function TemperatureConverter() {
  // State lives in the PARENT — shared between both inputs
  const [celsius, setCelsius] = useState('');
  const fahrenheit = celsius ? (celsius * 9/5 + 32).toFixed(1) : '';

  return (
    <div>
      <TemperatureInput value={celsius}      onChange={setCelsius} unit="°C" />
      <TemperatureInput value={fahrenheit} onChange={v => setCelsius((v-32)*5/9)} unit="°F" />
    </div>
  );
}

Real-World State Example — Shopping Cart

React 19 · ShoppingCart.jsx
import { useState } from 'react';

const PRODUCTS = [
  { id: 1, name: 'Pizza Slice', price: 3.99, emoji: '🍕' },
  { id: 2, name: 'Burger',     price: 5.49, emoji: '🍔' },
  { id: 3, name: 'Ice Cream',  price: 2.99, emoji: '🍦' },
];

function ShoppingCart() {
  const [cart, setCart] = useState({});

  const addItem = (id) =>
    setCart(prev => ({ ...prev, [id]: (prev[id] || 0) + 1 }));

  const removeItem = (id) =>
    setCart(prev => {
      const updated = { ...prev };
      if (updated[id] > 1) updated[id]--;
      else delete updated[id];
      return updated;
    });

  const total = PRODUCTS.reduce((sum, p) =>
    sum + (cart[p.id] || 0) * p.price, 0);

  return (
    <div>
      {PRODUCTS.map(p => (
        <div key={p.id}>
          <span>{p.emoji} {p.name} ${p.price}</span>
          <button onClick={() => addItem(p.id)}>+</button>
          <span>{cart[p.id] || 0}</span>
          <button onClick={() => removeItem(p.id)}>-</button>
        </div>
      ))}
      <h3>Total: ${total.toFixed(2)}</h3>
    </div>
  );
}
🤩 Fun Fact: React batches multiple setState calls in event handlers into a single re-render (since React 18). So three setState calls in one click handler result in only one re-render, not three! This automatic batching makes React fast.

State Machines & Complex State with useReducer

When a component has multiple state variables that always change together, or when the next state depends on complex conditional transitions, useReducer is often cleaner than multiple useState calls.

React 19 · useReducer pattern
import { useReducer } from 'react';

const initialState = { count: 0, step: 1, status: 'idle' };

function counterReducer(state, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + state.step, status: 'active' };
    case 'DECREMENT':
      return { ...state, count: state.count - state.step, status: 'active' };
    case 'SET_STEP':
      return { ...state, step: action.payload };
    case 'RESET':
      return initialState;
    default:
      return state;
  }
}

export function AdvancedCounter() {
  const [state, dispatch] = useReducer(counterReducer, initialState);

  return (
    <div className="counter-box">
      <h3>Count: {state.count} (Step: {state.step})</h3>
      <p>Status: {state.status}</p>
      <button onClick={() => dispatch({ type: 'INCREMENT' })}>+{state.step}</button>
      <button onClick={() => dispatch({ type: 'DECREMENT' })}>-{state.step}</button>
      <button onClick={() => dispatch({ type: 'RESET' })}>Reset</button>
      <input
        type="number"
        value={state.step}
        onChange={e => dispatch({ type: 'SET_STEP', payload: Number(e.target.value) })}
      />
    </div>
  );
}

State vs. Props vs. Local Variables

Feature State (useState) Props (props) Local Variable (let x)
Ownership Internal to component Passed from parent Function scope only
Mutated By Component via setter Parent only (read-only to child) Direct assignment
Causes Re-render? ✅ Yes, on setter call ✅ Yes, when parent re-renders new props ❌ No
Persists Across Renders? ✅ Yes, React remembers it ✅ Yes, parent manages lifecycle ❌ No, wiped on next render

Chapter 7 Summary

  • ✅ State is a component's private, mutable memory
  • ✅ useState(initialValue) returns [value, setter]
  • ✅ Calling the setter triggers a re-render
  • ✅ Never mutate state — always create new objects/arrays
  • ✅ Use the functional updater prev => newVal when new state depends on old
  • ✅ Lift state to the closest common parent when siblings need to share it
  • ✅ State differs from props: state is internal and mutable; props are external and read-only

🧠 Chapter 7 Quiz

Q1. What is returned by useState(42)?

Show Answer

✅ An array with two elements: [42, setterFunction]. The first is the current state value (42), the second is a function to update it.

Q2. What's wrong with: user.name = "Bob"; setUser(user);?

Show Answer

✅ You're mutating the state object directly. Since the object reference doesn't change, React may not detect the update. Always spread: setUser({...user, name: "Bob"}).

Q3. What does "lifting state up" mean?

Show Answer

✅ Moving state to the nearest common parent of two sibling components that both need that data. The parent holds state and passes it down via props.

Q4. Why use setCount(prev => prev + 1) instead of setCount(count + 1)?

Show Answer

✅ The functional form always reads the latest state value, even inside async callbacks or batched updates where count might be stale.

Q5. What is the difference between props and state?

Show Answer

✅ Props come from the parent, are read-only, and flow downward. State is owned by the component itself, is mutable, and triggers re-renders when changed via the setter.
