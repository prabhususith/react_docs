React Hooks Deep Dive

The fishing hooks that connect your component to React's superpowers

🎯 Learning Objectives

🎣 A Real-World Story: The Fishing Trip

Imagine you're on a fishing trip 🎣. You're sitting in a boat on a calm lake. Underneath the water is a whole world of fish, water plants, and currents — that's React's internal world (state, lifecycle, DOM). You can't just jump in and grab things — you'd disturb everything!

Instead, you use fishing hooks. Each hook is designed to catch something specific: a spinner lure catches bass, a fly lure catches trout. In React, each Hook is designed to access a specific superpower: useEffect catches "moments in time" (when the component mounts or updates), useRef catches a direct handle to a DOM element, useMemo catches a cached computation result.

The best fisherman knows which hook to use for which fish. The best React developer knows which Hook to reach for in each situation. By the end of this chapter, you'll be an expert angler! 🏆

📖
Definition — React Hook: A special function (always prefixed with use) that lets function components "hook into" React features like state, lifecycle, context, refs, and memoisation. Introduced in React 16.8, hooks replaced class component lifecycle methods.

The Rules of Hooks

⚠️
Two Unbreakable Rules:
  1. ✅ Only call Hooks at the top level — never inside loops, conditions, or nested functions
  2. ✅ Only call Hooks from React functions — components or custom hooks, never plain JS functions
These rules ensure React can track hook order correctly on every render.

🎣 Hook #2: useEffect — The Lifecycle Hook

useEffect lets you perform side effects: fetching data, subscribing to events, manipulating the DOM, setting timers — anything that reaches "outside" the component.

React 19 · useEffect patterns
import { useState, useEffect } from 'react';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  // Runs AFTER render, re-runs when userId changes
  useEffect(() => {
    let cancelled = false;   // for cleanup
    setLoading(true);

    fetch(`/api/users/${userId}`)
      .then(r => r.json())
      .then(data => {
        if (!cancelled) {   // only update if still mounted
          setUser(data);
          setLoading(false);
        }
      });

    // Cleanup function — runs before next effect or on unmount
    return () => { cancelled = true; };
  }, [userId]);  // dependency array — re-run only when userId changes

  if (loading) return <p>Loading...</p>;
  return <h2>{user?.name}</h2>;
}

// Three dependency array forms:
useEffect(() => { /* runs after EVERY render */ });
useEffect(() => { /* runs only ONCE on mount */ }, []);
useEffect(() => { /* runs when dep1 or dep2 changes */ }, [dep1, dep2]);

🎣 Hook #3: useMemo — The Cache Hook

React 19 · useMemo
import { useMemo } from 'react';

function ProductList({ products, searchTerm }) {
  // Recomputes ONLY when products or searchTerm changes
  const filtered = useMemo(() => {
    return products.filter(p =>
      p.name.toLowerCase().includes(searchTerm.toLowerCase())
    );
  }, [products, searchTerm]);

  return <ul>{filtered.map(p => <li key={p.id}>{p.name}</li>)}</ul>;
}

🎣 Hook #4: useCallback — Stable Function References

React 19 · useCallback
import { useCallback, memo } from 'react';

const Button = memo(({ onClick, label }) => {
  return <button onClick={onClick}>{label}</button>;
});

function Parent() {
  const [count, setCount] = useState(0);

  // Without useCallback, handleClick is new on EVERY render → Button re-renders
  // WITH useCallback, same function reference → Button is skipped ✅
  const handleClick = useCallback(() => {
    setCount(prev => prev + 1);
  }, []); // no deps — function never changes

  return (
    <div>
      <p>Count: {count}</p>
      <Button onClick={handleClick} label="Increment" />
    </div>
  );
}

🎣 Hook #5: useRef — The Persistence Hook

React 19 · useRef — two use cases
import { useRef, useEffect } from 'react';

function VideoPlayer() {
  // Use case 1: DOM reference
  const videoRef = useRef(null);

  const handlePlay = () => videoRef.current.play();
  const handlePause = () => videoRef.current.pause();

  return (
    <div>
      <video ref={videoRef} src="/movie.mp4" />
      <button onClick={handlePlay}>▶ Play</button>
      <button onClick={handlePause}>⏸ Pause</button>
    </div>
  );
}

function Timer() {
  // Use case 2: Persistent value that doesn't trigger re-render
  const intervalRef = useRef(null);
  const [seconds, setSeconds] = useState(0);

  const start = () => {
    intervalRef.current = setInterval(() => setSeconds(s => s+1), 1000);
  };
  const stop = () => clearInterval(intervalRef.current);

  return <div>{seconds}s <button onClick={start}>Start</button> <button onClick={stop}>Stop</button></div>;
}

Building Custom Hooks

Extract reusable stateful logic into your own custom hook:

React 19 · useFetch custom hook
import { useState, useEffect } from 'react';

// Convention: custom hooks start with "use"
function useFetch(url) {
  const [data,    setData]    = useState(null);
  const [loading, setLoading] = useState(true);
  const [error,   setError]   = useState(null);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);

    fetch(url, { signal: controller.signal })
      .then(r => r.json())
      .then(setData)
      .catch(e => { if (e.name !== 'AbortError') setError(e); })
      .finally(() => setLoading(false));

    return () => controller.abort();
  }, [url]);

  return { data, loading, error };
}

// Using the custom hook — SO clean!
function PostList() {
  const { data: posts, loading, error } = useFetch('/api/posts');
  if (loading) return <p>Loading...</p>;
  if (error)   return <p>Error: {error.message}</p>;
  return <ul>{posts.map(p => <li key={p.id}>{p.title}</li>)}</ul>;
}
🤩 Fun Fact: Popular libraries like react-query, swr, and zustand are largely built on custom hooks. When you master custom hooks, you can build your own state management library!

More Essential Built-in Hooks

🎣 Hook #6: useId — Unique Accessibility Identifiers

When connecting form labels to inputs (e.g. htmlFor="email"), hardcoded IDs cause clashes if the component is rendered multiple times on the same page. useId generates unique, server-safe IDs that remain stable across hydration.

React 19 · useId
import { useId } from 'react';

function FormField({ label, type = 'text' }) {
  const id = useId();
  return (
    <div className="form-group">
      <label htmlFor={id}>{label}</label>
      <input id={id} type={type} />
    </div>
  );
}

🎣 Hook #7: Custom Hook — useLocalStorage

Combine useState and useEffect to synchronize state automatically with the browser's local storage:

React 19 · useLocalStorage custom hook
import { useState, useEffect } from 'react';

export function useLocalStorage(key, initialValue) {
  const [storedValue, setStoredValue] = useState(() => {
    try {
      const item = window.localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch (error) {
      console.error(error);
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      window.localStorage.setItem(key, JSON.stringify(storedValue));
    } catch (error) {
      console.error(error);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}

Chapter 8 Summary

  • ✅ Hooks must be called at the top level and only inside React functions
  • ✅ useEffect runs after render; return a cleanup function for subscriptions
  • ✅ The dependency array controls when useEffect re-runs
  • ✅ useMemo caches a computed value; useCallback caches a function
  • ✅ useRef gives DOM access and stores values without triggering re-renders
  • ✅ Custom hooks (prefixed use) extract and share stateful logic cleanly

🧠 Chapter 8 Quiz

Q1. What are the two rules of hooks?

Show Answer

✅ 1) Call hooks only at the top level (not inside loops/conditions). 2) Call hooks only inside React function components or custom hooks.

Q2. What does an empty dependency array [] mean for useEffect?

Show Answer

✅ The effect runs only once — after the initial render (component mount). It never re-runs due to state/prop changes.

Q3. What is the difference between useMemo and useCallback?

Show Answer

✅ useMemo memoizes a computed value (the result of calling a function). useCallback memoizes the function itself (its reference), useful for passing stable callbacks to child components.

Q4. Name two use cases for useRef.

Show Answer

✅ 1) Accessing a DOM element directly (e.g., focus an input, control video playback). 2) Storing a mutable value that persists across renders without causing re-renders (e.g., interval ID, previous value).

Q5. How do you name a custom hook and why?

Show Answer

✅ Always start with use (e.g., useFetch, useLocalStorage). This naming convention is required so the React linter can enforce hook rules on your custom hook.
