🚰 A Real-World Story: The City Water Supply

Imagine living in a giant apartment building with two hundred apartments 🏢. Every morning, people need fresh water to brush their teeth, make coffee ☕, and take showers.

What if there were no pipes in the building? Every morning at 6:00 AM, each tenant would have to walk down twenty flights of stairs with heavy plastic buckets, walk to the town well, fill their buckets, carry them all the way back up the stairs, and store them in their living room! That would be exhausting, messy, and slow. If five people in a row needed a cup of water, they would spend their whole day passing buckets up and down the stairwell (just like prop drilling in code!).

Instead, modern buildings have a plumbing system! There is one clean municipal water tower on top of the hill. Copper pipes run through the walls behind every room. Whenever you want water, you don't hike to the well—you just turn on the kitchen tap 🚰, and fresh water pours out on demand!

That is exactly what Angular Services and Dependency Injection do! Your components don't create their own data fetchers or pass data through twenty layers of parent components. They simply declare: "Hey Angular, please connect me to the UserService tap!" And Angular instantly hooks up the pipe! 💧✨

What is Dependency Injection?

Dependency Injection (DI) is a design pattern where a class does not instantiate its own dependencies (such as HTTP clients, logging services, or database stores) using new MyService(). Instead, an external entity—the Injector—creates and supplies those dependencies.

📖
Definition — Singleton Service: An object instance created only once by the root injector. Every component in the application that requests this service receives a reference to the exact same shared instance, maintaining synchronized global state.

Modern Functional Injection with inject()

In older versions of Angular, developers had to write lengthy constructor signatures. In modern Angular (v14+), you can use the clean, elegant inject() function directly in class property initializers!

Angular · Old Constructor vs Modern inject()
// ❌ Older Angular Constructor Injection (verbose boilerplate)
export class LegacyComponent {
  constructor(
    private authService: AuthService,
    private router: Router,
    private http: HttpClient
  ) {}
}

// ✅ Modern Angular Functional Injection (clean & readable!)
export class ModernComponent {
  private authService = inject(AuthService);
  private router      = inject(Router);
  private http        = inject(HttpClient);
}

💻 For Developers — Building an Enterprise Service

Let's build a real-world Angular service combining the @Injectable decorator, modern Angular Signals, and the built-in HTTP client.

Angular · cart.service.ts
import { Injectable, signal, computed, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

export interface CartItem {
  id: number;
  name: string;
  price: number;
  quantity: number;
}

/**
 * providedIn: 'root' registers this service with the application-wide root injector.
 * It is tree-shakable: if unused, the bundler excludes it from production bundles!
 */
@Injectable({
  providedIn: 'root'
})
export class CartService {
  private http = inject(HttpClient);

  // Reactive Signal State
  private itemsSignal = signal<CartItem[]>([]);

  // Read-only public signal for components
  items = this.itemsSignal.asReadonly();

  // Computed signals automatically recalculate when itemsSignal changes
  itemCount = computed(() =>
    this.itemsSignal().reduce((sum, item) => sum + item.quantity, 0)
  );

  totalPrice = computed(() =>
    this.itemsSignal().reduce((sum, item) => sum + (item.price * item.quantity), 0)
  );

  addItem(newItem: CartItem) {
    this.itemsSignal.update(items => {
      const existing = items.find(i => i.id === newItem.id);
      if (existing) {
        return items.map(i => i.id === newItem.id
          ? { ...i, quantity: i.quantity + newItem.quantity }
          : i
        );
      }
      return [...items, newItem];
    });
  }

  clearCart() {
    this.itemsSignal.set([]);
  }
}
💡 Tree-Shaking Superpower: By setting providedIn: 'root', you enable Angular's build optimizer to inspect whether your app ever actually imports the service. If not, the entire class is deleted from your production JavaScript bundle!

Hierarchical Injector Tree: Root vs. Scoped Services

Angular doesn't just have one global injector—it possesses a hierarchical tree of injectors mirroring your component hierarchy.

Angular Dependency Injection vs React Context API

Aspect Angular Dependency Injection React Context API
Mechanism Class tokens registered with DI container Context objects with <Provider value={...}> wrappers
Tree Dependency Can be injected anywhere without wrapping DOM elements Must be wrapped by a JSX Provider higher up in the component tree
Unit Testing Easy mocking via TestBed.configureTestingModule() Must mock provider wrappers or pass custom test values
Lifecycle Managed automatically by injector tier (singleton or component destroyed) Bound strictly to the lifespan of the Provider component
Fine-Grained Updates Combined with Angular Signals, only reading nodes re-render All consumers re-render when context value object changes (unless memoized)
⚠️ Common React Pitfall in Angular: In React, creating a provider at the root of your app is standard practice. In Angular, you do NOT need to wrap your component in a <ServiceProvider>! Simply adding @Injectable({ providedIn: 'root' }) makes it available everywhere automatically.

🛠️ Try It Yourself!

Plumbing Challenge: The High-Score Leaderboard Service

Construct a leaderboard service for an online gaming platform:

  • Use @Injectable({ providedIn: 'root' }).
  • Store scores in an internal Signal array: { player: string, score: number }.
  • Create a computed signal topThree that sorts descending and returns the top 3 scores.
  • Create a component that uses inject(LeaderboardService) and displays the top players!
Solution blueprint · leaderboard.service.ts
import { Injectable, signal, computed } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class LeaderboardService {
  private scores = signal([
    { player: 'PixelKnight', score: 9800 },
    { player: 'DragonSlayer', score: 8750 },
    { player: 'ShadowNinja', score: 11200 }
  ]);

  topThree = computed(() =>
    [...this.scores()]
      .sort((a, b) => b.score - a.score)
      .slice(0, 3)
  );

  recordScore(player: string, score: number) {
    this.scores.update(list => [...list, { player, score }]);
  }
}

🧠 Chapter 12 Quiz

Q1. What does providedIn: 'root' do inside an @Injectable decorator?

Show Answer

✅ It registers the service with the application-wide root injector as a tree-shakable singleton. Every component asking for it shares the exact same instance.

Q2. What happens if you register a service in a component's providers: [MyService] array?

Show Answer

✅ Angular creates a new, private instance of MyService scoped specifically to that component and its children. When that component is unmounted from the DOM, the service instance is destroyed.

Q3. How does modern Angular's inject() function improve on constructor injection?

Show Answer

✅ It removes the need for large, repetitive constructor parameter lists and allows dependencies to be declared directly as class field initializers.

Q4. Compare Angular DI with React Context: which one requires wrapping JSX elements?

Show Answer

✅ React Context requires a <MyContext.Provider> element to wrap the component subtree. Angular DI requires no JSX/HTML wrappers—the injector tree supplies dependencies based on TypeScript tokens.

Q5. What does "Inversion of Control" mean in the context of Angular services?

Show Answer

✅ Instead of a component controlling how and when its dependencies are created (via new), control is inverted: the framework's injector handles instantiation, lifecycle, and injection.
