Need quick, clean simplicity? Zustand gets you back to building toys in ten seconds flat! 🚀⚡

cart.reducer.ts
import { createReducer, on } from '@ngrx/store';
import { addItem, removeItem, clearCart, CartItem } from './cart.actions';

export interface CartState {
  items: CartItem[];
  total: number;
}

export const initialState: CartState = {
  items: [],
  total: 0
};

export const cartReducer = createReducer(
  initialState,
  on(addItem, (state, { item }) => ({
    ...state,
    items: [...state.items, item],
    total: state.total + item.price
  })),
  on(removeItem, (state, { id }) => ({
    ...state,
    items: state.items.filter(i => i.id !== id),
    total: state.items
      .filter(i => i.id !== id)
      .reduce((sum, i) => sum + i.price, 0)
  })),
  on(clearCart, () => initialState)
);
useCartStore.ts (Zustand)
import { create } from 'zustand';
import { devtools, persist } from 'zustand/middleware';

export interface CartItem {
  id: string;
  name: string;
  price: number;
}

interface CartState {
  items: CartItem[];
  addItem: (item: CartItem) => void;
  removeItem: (id: string) => void;
  clearCart: () => void;
  total: () => number;
}

export const useCartStore = create<CartState>()(
  devtools(
    persist(
      (set, get) => ({
        items: [],
        addItem: (item) =>
          set(state => ({ items: [...state.items, item] })),
        removeItem: (id) =>
          set(state => ({
            items: state.items.filter(i => i.id !== id)
          })),
        clearCart: () => set({ items: [] }),
        total: () =>
          get().items.reduce((acc, cur) => acc + cur.price, 0)
      }),
      { name: 'cart-storage' }
    )
  )
);
Alternative: Redux Toolkit (RTK) Slice
import { createSlice, PayloadAction } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] as CartItem[] },
  reducers: {
    addItem: (state, action: PayloadAction<CartItem>) => {
      state.items.push(action.payload); // Immer handles immutability!
    },
    removeItem: (state, action: PayloadAction<string>) => {
      state.items = state.items.filter(i => i.id !== action.payload);
    }
  }
});
export const { addItem, removeItem } = cartSlice.actions;
export default cartSlice.reducer;
CartComponent (TypeScript & Template)
import { Component } from '@angular/core';
import { Store } from '@ngrx/store';
import { Observable } from 'rxjs';
import { addItem, removeItem } from './cart.actions';
import { selectCartItems, selectCartTotal } from './cart.selectors';

@Component({
  selector: 'app-cart',
  template: `
    <div class="cart-box">
      <h3>Cart Items ({{ (items$ | async)?.length }})</h3>
      <ul>
        <li *ngFor="let item of items$ | async">
          {{ item.name }} - \${{ item.price }}
          <button (click)="onRemove(item.id)">✕</button>
        </li>
      </ul>
      <p>Total: \${{ total$ | async }}</p>
    </div>
  `
})
export class CartComponent {
  items$: Observable<CartItem[]> = this.store.select(selectCartItems);
  total$: Observable<number> = this.store.select(selectCartTotal);

  constructor(private store: Store) {}

  onRemove(id: string) {
    this.store.dispatch(removeItem({ id }));
  }
}
Cart.tsx Component (React)
import React from 'react';
import { useCartStore } from './useCartStore';

export function Cart() {
  // Subscribing ONLY to items and removeItem prevents total recalculations from re-rendering
  const items = useCartStore(state => state.items);
  const removeItem = useCartStore(state => state.removeItem);
  const total = useCartStore(state => state.total());

  return (
    <div className="cart-box">
      <h3>Cart Items ({items.length})</h3>
      <ul>
        {items.map(item => (
          <li key={item.id}>
            {item.name} - ${item.price}
            <button onClick={() => removeItem(item.id)}>✕</button>
          </li>
        ))}
      </ul>
      <p>Total: ${total}</p>
    </div>
  );
}

Pro Deep Dive 🧠

The Mental Shift: Server State vs Client State: Before adopting NgRx or Redux, ask: "Is this truly client state, or is it merely a cache of backend data?" Over 80% of data traditionally stored in Redux/NgRx stores (user profiles, product catalogs, paginated lists) is Server State. Modern best practice favors using specialized caching engines (Angular's TanStack Query or HTTP interceptor caches; React's TanStack Query) for network resources, reserving NgRx/Zustand purely for true Client UI State (drawer open state, active filter chips, multi-step unsaved wizard data).

Memoized Selectors and Tree-shaking: NgRx's createSelector() calculates derivations only when its specific input selectors emit new object references. However, because RxJS pipelines use closures, improper destruction without the async pipe or takeUntilDestroyed() causes memory leaks. Zustand bypasses RxJS completely: it utilizes useSyncExternalStore under the hood to guarantee tear-free concurrent renders in React 18 & 19 without wrapper Context providers.

NgRx ComponentStore & SignalStore (Angular 16+): For features where global NgRx is overkill, the Angular team released @ngrx/signals. The signalStore allows writing reactive stores with signals, offering a lightweight developer experience remarkably similar to Zustand while retaining Angular's DI capabilities.

Real-World Scenario: Complex B2B SaaS Flight Booking Engine ✈️

A corporate travel app allows booking flights with multiple layovers, traveler seat assignments, luggage add-ons, and dynamic currency conversions.

  • With NgRx: Every step (selecting outbound flight, adding hotel combo, applying company discount voucher) dispatches an action. NgRx Effects intercept voucher application, call credit check APIs, and emit applyVoucherSuccess. The entire booking history is replayable in Redux DevTools, allowing customer support engineers to export the exact JSON action sequence to reproduce ticket purchase bugs. ✈️📑
  • With Zustand: A lightweight store useBookingFlow() holds active flight selections with local storage persistence enabled via middleware. Transient UI states (seat hover previews, currency toggles) execute with 0ms overhead and zero boilerplate files.

🅰️ When to Choose NgRx

  • You manage massive, multi-team enterprise apps requiring rigid architectural rules
  • Auditability, time-travel debugging, and strict action logging are legal or SLA requirements
  • Your team is already deeply proficient in RxJS operators (switchMap, exhaustMap)
  • You require complex state orchestration across dozens of disconnected micro-frontends

⚛️ When to Choose Zustand / Redux Toolkit

  • You want to ship fast with minimal boilerplate and maximum readability
  • Your app needs state access outside React components (inside utility functions or websockets)
  • You prioritize atomic rendering performance without context re-render cascades
  • You prefer simple vanilla JS objects over complex class hierarchies and actions

createAction() — NgRx: Declare an action intent with typed payload
createReducer() — NgRx: Pure function responding to actions
createSelector() — NgRx: Memoized selector calculation
createEffect() — NgRx: Listen to action streams for async side-effects
create() — Zustand: Build a reactive custom hook store

Modern Evolution: @ngrx/signals (SignalStore) vs Zustand Atomic Slices

Angular 16+ introduced signalStore, blending the simplicity of Zustand with Angular's Dependency Injection system!

🅰️ Angular: @ngrx/signals (SignalStore) ⚛️ React: Zustand Atomic Selector Slices
cart.store.ts (@ngrx/signals)
import { signalStore, withState, withMethods, withComputed, patchState } from '@ngrx/signals';
import { computed } from '@angular/core';

export const CartStore = signalStore(
  { providedIn: 'root' },
  withState({
    items: [] as { id: string; name: string; price: number }[],
    isLoading: false
  }),
  withComputed(({ items }) => ({
    totalCount: computed(() => items().length),
    totalPrice: computed(() => items().reduce((acc, i) => acc + i.price, 0))
  })),
  withMethods((store) => ({
    addItem(item: { id: string; name: string; price: number }) {
      patchState(store, (state) => ({ items: [...state.items, item] }));
    },
    clear() {
      patchState(store, { items: [] });
    }
  }))
);

// In Component: inject(CartStore).items() — pure signals!
cartSlice.ts (Zustand Slices Pattern)
import { StateCreator } from 'zustand';

export interface CartSlice {
  items: { id: string; name: string; price: number }[];
  addItem: (item: { id: string; name: string; price: number }) => void;
  clear: () => void;
}

export const createCartSlice: StateCreator<CartSlice> = (set) => ({
  items: [],
  addItem: (item) =>
    set((state) => ({ items: [...state.items, item] })),
  clear: () => set({ items: [] })
});

// Combined Store:
import { create } from 'zustand';
export const useAppStore = create<CartSlice>()((...a) => ({
  ...createCartSlice(...a)
}));

Quiz Time! 🎯

  1. What is the fundamental difference between an Action and a Reducer in NgRx?
    AnswerAn Action describes what happened (the intent/event), while a Reducer is a pure function that calculates how the state changes in response to that action.
  2. Why does Zustand not require a <Provider> component wrapped around your React app?
    AnswerZustand stores are external module-level closures. Components subscribe to them directly using React's useSyncExternalStore hook, bypassing the React Context tree completely.
  3. What is an NgRx Effect used for?
    AnswerEffects handle asynchronous side effects (such as fetching data over HTTP, logging analytics, or reading browser storage) without polluting pure reducer functions.
  4. When should you use Server Cache libraries (like TanStack Query) instead of NgRx/Redux?
    AnswerWhen data originates from an external server (REST/GraphQL endpoints) that needs caching, background revalidation, and loading/error states, TanStack Query is much better suited than hand-crafted global stores.
